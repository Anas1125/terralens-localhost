# Applicant resume privacy

The public media endpoint previously included applications/ files and the Vercel Blob uploader stored resumes as public objects. New submissions store resume bytes in the private_resumes database table, with the application and resume committed together. Admin downloads use an authenticated attachment endpoint; no public upload URL for new resumes. Existing local applications/ files are excluded from public static serving; legacy local files can be downloaded through the same authenticated route. New resumes limited to 4 MiB and inactive job submissions are rejected.

**Existing public Blob files remain public until migrated and removed.** Do not assume hiding URLs revokes access. Review prior applications and Blob objects privately, preserve necessary records in access-controlled storage, verify migration, delete the public copies, review logs and consider applicable breach-response obligations. Do not print resume URLs, names or contents in logs or chats. Legacy public Blob downloads are intentionally not linked by the new admin UI; migration required. Existing public media is otherwise unchanged. A new table is created by existing create_all; production database permissions must allow it. PDF checks remain basic signature checks; antivirus/content scanning is a separate milestone. The authenticated download forces attachment; do not open untrusted PDFs on sensitive systems. Local test and browser verification required.
